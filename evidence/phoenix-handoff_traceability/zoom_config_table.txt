STEP 3 — CRITICAL QUESTION: Do all 4 encoder configs share ONE R_fold or have different R_folds?
------------------------------------------------------------------------------

The factory CSV stores EXACTLY ONE R_fold per movable camera.
The warp block stores ONLY encoder positions + per-position distortion grids.
There is NO per-config R_fold stored anywhere in the data — one R_fold per camera.

Implication: all 4 encoder positions for a given camera point at the SAME azimuth.
The encoder position controls FOCAL LENGTH (zoom), not viewing direction.

EVIDENCE: The 4 warp grids per camera are DISTINCT (different distortion per focal pos),
but no directional rotation matrix changes between configs.

STEP 5 — DO CONFIGS 0..3 DIFFER IN AZIMUTH?
==============================================================================

ANSWER: NO. All 4 encoder configs for every movable camera share the SAME azimuth.

The factory calibration CSV stores exactly one R_fold (3×3 rotation) per movable camera.
R_fold does NOT change between encoder positions. Only the per-position distortion
correction grid (17×13 float32) changes between configs — this encodes the focal-length-
dependent geometric distortion at that zoom position.

Encoder positions map to FOCAL LENGTHS (zoom), not to different look directions:

  B1:  encoder [622, 490, 362, 748] → 4 focal positions, all az ≈ -37.8°
  B2:  encoder [582, 463, 342, 698] → 4 focal positions, all az ≈ -144.1°
  B5:  encoder [801, 663, 531, 917] → 4 focal positions, all az ≈  +35.9°
  C1:  encoder [632, 528, 418, 739] → 4 focal positions, all az ≈  +36.1°
  C4:  encoder [764, 651, 539, 874] → 4 focal positions, all az ≈ +143.1°

  B3, C2, C3: only 1 config (encoder=0) → effectively glued in this unit

Azimuth clustering summary:
  az ≈ -140°: B2, C2
  az ≈  -40°: B1, C3
  az ≈  +40°: B5, C1
  az ≈ +140°: B3, C4

The 8 movable cameras cluster into 4 azimuth quadrants (±37°, ±143°),
each quadrant covered by one B camera + one C camera pair.
This is consistent with Architecture (b): aperture-mosaic tiles at 4 corners.

INVESTIGATION ANSWER — what this resolves
==============================================================================

Open question from investigation doc:
  "do all 4 configs for a movable camera point at the SAME azimuth (they just
   differ in focal length/zoom), or at DIFFERENT azimuths?"

ANSWER: SAME AZIMUTH. All 4 encoder configs for a given movable camera point
at one fixed azimuth. The encoder position selects focal length (zoom level),
not pointing direction. This means:

  Architecture (b) — aperture-mosaic tiles — remains the leading hypothesis.
  Each movable camera covers ONE corner/edge quadrant of the scene at all zoom levels.
  There is no mechanism by which a movable camera changes its look-direction
  between captures; the mirror is factory-glued after calibration.

  The investigation task brief claim that "all B cameras used config 2 at 28mm"
  is not a distinct R_fold selection — it is a focal-length bracket selection.
  Config index 2 = encoder 362 for B1 (the closest-focus position in the bracket).

  The "selected config" for this capture (02586) based on CSV nominal encoder:
    B1  : nom_enc=490.6  → config[1]=490
    B2  : nom_enc=651.4  → config[3]=698
    B3  : nom_enc=574.0  → config[0]=0
    B5  : nom_enc=675.2  → config[1]=663
    C1  : nom_enc=656.6  → config[0]=632
    C2  : nom_enc=458.2  → config[0]=0
    C3  : nom_enc=543.0  → config[0]=0
    C4  : nom_enc=524.2  → config[2]=539

  Note: B3, C2, C3 have encoder=0 (single config) in both tested LRI files,
  consistent with those cameras being permanently glued to one position.
