=== ANSWERS TO 4 INVESTIGATIVE QUESTIONS ===

Q1: How many input Bayer planes are fused (camera count N)?
    ANSWER: N=1 for ALL 132 tiles measured in this render.
    The multi-camera blend path (N>=2 -> 0x1bd0a0) was NEVER triggered.
    The code supports N>=2 (it exists in the binary) but was not exercised.
    INTERPRETATION: FusionCacheBayer receives pre-merged Bayer data. The 10
    L16 cameras are fused at an earlier pipeline stage before FusionCacheBayer.
    img_vec[0] holds one pre-assembled panoramic Bayer strip per tile.

Q2: Are weight/confidence maps passed alongside pixel data?
    ANSWER: No per-pixel weight map. A per-tile scalar weight is used:
    xmm0 at PackedBayerFusion entry = sqrt(tile_exposure).
    When N>=2: xmm0 = sqrt(width * height * exposure) / N.
    No separate confidence map pointer observed in any object dump.

Q3: Is blending linear/seam/pyramid?
    ANSWER: LINEAR WEIGHTED AVERAGE (not Laplacian pyramid).
    LaplacianPyramid blend lambda at 0x1ab010: 0 hits across all runs.
    PyramidWorker at 0x1ab2d0: 1 hit (initialization only, not blending).
    When N>=2: blend = weighted_sum(pixels) / N using sqrt exposure weights.
    Blend is performed in Bayer domain (pre-demosaic).

Q4: Are per-pixel decisions made?
    ANSWER: YES -- inner kernel 0x19c790 is a per-pixel vectorized loop.
    Decisions (clamping, black-level subtraction) happen inside the 21KB kernel.
    No per-pixel confidence threshold was observed at the FusionCacheBayer level.
