# Unsharp Formula: Installed Proof and Four-Focal Runtime Replay

## Result

The selected `SharpenLineFactory<float>` worker is a CIE Lab lightness-only
difference-of-Gaussians boost. For each scalar sample, in installed float32
order:

```text
L       = LabLineFactory(input).L_star
dog     = gaussian_positive(L) - gaussian_negative(L)
boost   = clamp(amount * dog, -20.0, 20.0)
L_out   = L + boost
```

This is not per-RGB unsharp masking and is not `input + amount*(input-blur)`.
The base source has exact RTTI
`LabLineFactory<Image<vec4x32f>>`; the first returned plane is CIE `L*`.
The SHA-pinned Lab body uses the defining output constants `116` and `-16`
for `L*`, followed by `500` and `200` for the two chroma planes. The sharpen
worker receives and modifies the first scalar plane.

The generic amount is object field `+0x68`, copied from constructor config
`+0x0c`. Every first live combine packet at Unit-1 28mm, 35mm, 70mm, and
150mm uses `amount=1.0` and replays bit-for-bit. Complete constructor censuses
at all four tiers contain exactly seven unique five-float packets apiece and
the configured amount set is `{0.5,1.0}`.

The five-float packet and its kernel-width policy are now closed. The packet
is copied directly as:

```text
(CameraModule.sensor_analog_gain,
 grain_power,
 grain_sigma,
 sharpening,
 sharpening_scale)
```

It is not generated by an image-local seven-way selector. The seven unique
packets are the seven distinct per-capture/shared-stage packets encountered
by these renders. Public `vibrance` selects one of three surrounding color
helper variants at tight thresholds around `1`; every variant passes the same
five-float packet to the sharpen constructor when `sharpening > 1e-6`.

## Exact kernel-width formula

Let `g=sensor_analog_gain`, `a=sharpening`, and
`s=sharpening_scale`. Every arithmetic operation below is rounded to
float32 in the written order. `clamp01(x)=max(0,min(1,x))`.

```text
if g < 1:
  P=1; A=1.2999999523162842; B=1; C=0.5
elif g < 2:
  t=clamp01(g-1)
  P=1
  A=1.2999999523162842 + 0.19999998807907104*t
  B=(0.5 + 0.10000002384185791*t) + 0.5
  C=0.5
elif g < 4:
  t=clamp01((g-2)*0.5)
  P=1 + 0.10000002384185791*t
  A=1.5 + 0.10000002384185791*t
  C=0.5 + 0.050000011920928955*t
  B=(0.6000000238418579 - 0.10000002384185791*t) + C
elif g < 7.75:
  t=clamp01((g-4)*0.2857142984867096)
  P=1.100000023841858 - 0.10000002384185791*t
  C=0.550000011920929 - 0.050000011920928955*t
  A=(0.5 - 0.4000000059604645*t) + P
  B=0.5 + C
else:
  P=1; A=1.100000023841858; B=1; C=0.5

q = clamp01((a-4)*0.0833333358168602)
positive_unscaled = P + q*(C-P)
radial            = A + q*(B-A)
sigma_positive    = positive_unscaled*s
sigma_negative    = sqrt(positive_unscaled^2 + radial^2)*s
```

The installed selector uses a 3-tap generator for `sigma <= 1`, 5 taps for
`1 < sigma <= 1.2999999523162842`, and 7 taps above that. The Gaussian
generator is the previously SHA-pinned normalized centered generator at
`0x96980`. Note that `a` is both the Lab-`L*` DoG boost amount and, only over
the interval `4..16`, the interpolation control for kernel width.

The independent verifier replays the observed Unit-1 `28mm` families:

```text
(g=1, a=1, s=1)   -> sigma_positive=1,
                      sigma_negative=1.6401219367980957
(g=1, a=1, s=0.5) -> sigma_positive=0.5,
                      sigma_negative=0.8200609683990479
(g=1.5, a=0.5, s=1) -> sigma_positive=1,
                        sigma_negative=1.720465064048767
```

## Scope

tap selector are SHA-pinned installed-bundle proof and are focal-independent.

body or firmware cause is inferred from the one-body runtime scope.
