# Reading Protocol

## Order of reading (canonical)

1. **This file** — establishes the rules.
2. **`docs/TRUTH.md`** — the single source of truth for L16 Phoenix architecture. Contains verified findings, refuted claims, and replication recipes.
3. **`docs/LIBRARY_INVENTORY.md`** — 411-symbol libcp public API + DepthEditor surface. Still accurate, no refutations.
4. **`CONTAMINATION_RULES.md`** — what NEVER to read as authoritative, and why.

## When TRUTH.md cites an evidence file

- Evidence lives at `/Volumes/Dev/lumen-phoenix-scratch/*.md` (100+ agent reports).
- `evidence/` in this repo is a directory pointing there via `evidence/README.md`. Do not try to read `evidence/<name>.md` directly inside the repo — read the full scratch path.
- Only read evidence files when TRUTH.md explicitly cites them. Do not browse the scratch dir looking for "more context" — that re-introduces contamination.

## When you encounter an archived doc

- `archive/*` contains deprecated content kept for audit trail.
- NEVER read archive content to inform current-architecture decisions.
- Archive is read-only. A pre-commit hook (`hooks/pre-commit`) rejects modifications.
- If you find yourself needing an archived fact, stop and ask: is this in TRUTH.md? If not, is it really still true? Do not silently lift claims from archive.

## When you find a conflict

- Between TRUTH.md and an archive doc: TRUTH wins.
- Between TRUTH.md and an evidence doc: TRUTH.md should cite the evidence. If TRUTH contradicts its own cited evidence, flag it — this is a real investigation gap, NOT a place for the reader to guess.
- Between TRUTH.md and runtime LLDB output: flag it. Do not silently adjust either side.

## When updating TRUTH.md

- Write a new dated copy: `docs/phoenix-truth-<YYYY-MM-DD>.md`.
- Update `docs/TRUTH.md` as a pointer (symlink or 1-line include) to the latest dated copy.
- Move the previous dated copy to `archive/` with a commit message referencing what changed.
- Never edit an old dated truth doc in place — those are immutable history.

## When writing spike code

- Spike = throwaway validation. Lives in `spike/`.
- Spike reads from TRUTH.md. It does NOT write to TRUTH.md.
- Spike outputs (MAD, per-region deltas) go into `spike/` as comments or side files, never into `docs/`.
- If spike fails, debug the spike OR flag the TRUTH finding for re-verification — never update TRUTH to match a failing spike output.

## When a session summary points to an old doc

- Session summaries generated by conversation-compaction are often stale. They reference docs by name (e.g., "doc 23"), which can lead to reading `Documents/Light_Work/docs/reverse_engineering/23_*.md` — a SEPARATE research thread, not the truth doc.
- Treat session summaries with suspicion. Verify any cited doc path against `docs/TRUTH.md` before reading.

## Enforcement

- Agents/assistants acknowledge this protocol by reading `docs/TRUTH.md` before making any architecture claim.
- `hooks/pre-commit` rejects modifications under `archive/`.
- CONTAMINATION_RULES.md lists the specific stale paths that look authoritative — check that list before reading any doc whose filename contains `phoenix`, `lumen`, or `current-state`.
